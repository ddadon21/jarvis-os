# SOP-006 — Week-One Live Operating Trial

**Version:** 1.0  
**Owner:** Dwight + JARVIS  
**Authority:** HJV Constitution v1.0

## Purpose
Use Jarvis as the real operating system for seven days before adding more employees or major features.

## Freeze rule
During the trial, no new permanent agent roles and no major new product lane unless a critical blocker requires it.

## Daily use
Dwight should use Jarvis normally for:
- Life;
- Trading / Observer;
- Finance;
- SentryOps;
- Workforce.

## Measure
### Observer
- state-detection latency;
- missing-field rate;
- wrong-symbol rate;
- false order/trade events;
- cancel-clear latency;
- per-symbol reliability.

### Workforce
- tasks started;
- tasks actually completed;
- verified completion rate;
- blocked/error count;
- unnecessary Founder interruptions;
- repeated failures;
- useful agent-to-agent handoffs.

### Company
- verified Lifetime Earned;
- new verified revenue events;
- unresolved incidents;
- uptime/provider degradation;
- open Founder approvals.

## Daily close
JARVIS produces a short brief:
- completed;
- failed/blocked;
- what changed;
- what needs Dwight;
- what should remain untouched.

## End-of-week review
Do not ask “what else can we add?” first.
Ask:
1. What worked without Dwight?
2. What repeatedly failed?
3. Which agent produced useful outcomes?
4. Which agent generated activity without value?
5. What SOP is missing because the same confusion happened twice?
6. Is another employee actually justified?
7. Is the Observer reliable enough to expand?
8. What is the single next bottleneck?

## Definition of done
Seven days of evidence produce a ranked repair list. Expansion happens only after the reliability gaps are understood.
